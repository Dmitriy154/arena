# CODEBUDDY.md

Правила работы ИИ-ассистента в этом проекте. Цель — маленькие точные правки
без чтения всего кода.

## 1. Порядок входа в задачу

1. Прочитать `docs/GAME_DESIGN.md` — там текущие правила и числа.
2. Найти нужный файл в карте ниже.
3. Открыть только этот файл. Если он большой — искать по символу через grep и
   читать диапазон вокруг совпадения, а не файл целиком.
4. Менять минимум кода. Не рефакторить соседний код «заодно».

Запрещено: читать весь `src` «для контекста», переписывать `BattleScene` целиком,
менять числа баланса без правки `GAME_DESIGN.md`.

## 2. Карта кода

| Файл | Ответственность | Когда трогать |
| --- | --- | --- |
| `src/main.ts` | конфиг Phaser, список сцен | новая сцена, размеры окна |
| `src/game/constants.ts` | все числовые константы мира и камеры | новые числа, а не хардкод в сцене |
| `src/game/types.ts` | типы, `UNIT_TYPES`, `FACTIONS` | новый тип отряда, нация, свойство |
| `src/game/entities/Unit.ts` | один отряд: вид, выделение, движение к точке | поведение отдельного юнита |
| `src/game/scenes/BattleScene.ts` | бой: ввод, выделение, приказы, расталкивание, HUD | игровой цикл и взаимодействие |
| `src/game/systems/CameraController.ts` | зум и панорама | только камера |
| `src/game/systems/Terrain.ts` | патчи леса и воды: проходимость, скорость, скрытность | новые типы местности, правка раскладки |
| `src/game/systems/Pathfinder.ts` | A* по сетке, сглаживание пути | маршруты, обход препятствий |
| `src/game/systems/Formation.ts` | точки строя, порядок отрядов, привязка к местности | формация, углы, раздача мест |
| `src/game/systems/MoveOrderSystem.ts` | приказ в точку и строем, маркер приказа | изменение приказов движения |
| `src/game/systems/FormationPreview.ts` | призрак строя в worldLayer | отрисовка превью построения |
| `src/game/systems/CursorView.ts` | свой курсор: размер и цвет по состоянию | обратная связь по наведению и режимам мыши |
| `src/game/systems/FogOfWar.ts` | два слоя тумана, видимость врагов | обзор, разведка, скрытность |
| `src/game/scenes/BootScene.ts` | генерация текстур | ассеты и процедурные текстуры |
| `src/game/scenes/MenuScene.ts` | меню | только меню |
| `src/game/ui/MenuButton.ts` | кнопка меню | UI-компоненты |

Правило роста: новая механика — новый файл в `src/game/systems/`
(например `CombatSystem.ts`, `EnemyAi.ts`), а сцена только вызывает систему.
Сцена не должна разрастаться: если в `BattleScene` больше ~700 строк, механика
выносится наружу.

## 3. Инварианты, которые нельзя ломать

- Две камеры: основная рисует мир, UI-камера — HUD. Новая графика HUD идёт в
  `uiLayer`, мировая — в `worldLayer`.
- Все отряды лежат в одном массиве `units`; принадлежность — через `faction`,
  а не через отдельные массивы.
- Выделяются только `unit.isPlayerControlled`.
- Числа не хардкодятся в сцене: константы — в `constants.ts`, баланс — в `types.ts`.
- TypeScript strict: без `any`, без `@ts-ignore`.
- Порядок отрисовки юнитов — `unitsLayer.sort('y')` при движении.
- Порядок в `worldLayer`: земля → местность → `unitsLayer` → туман → рамка выделения.
  Всё, что должно быть видно сквозь туман, добавляется после тумана.
- Туман стирается только через blend mode ERASE — фича работает только на WebGL.
- Проходимость и скорость всегда спрашиваются у `Terrain`, в сцене и юните нет
  проверок координат «на глаз».
- Движение задаётся только через `Unit.moveAlong(points)`. Прямых приказов
  «иди в точку» в обход A* нет.

## 4. Шаблон постановки задачи

Одна задача — одна механика. Формат:

```
Механика: <название>
Поведение: <что должно происходить, с числами>
Файлы: <какие трогать>
Не трогать: <соседние механики>
Готово когда: <наблюдаемый результат в игре>
```

Пример:

```
Механика: расход морали при движении
Поведение: мораль падает на 3 в секунду при движении, восстанавливается на 5
в секунду в покое, клампится в 0..100
Файлы: src/game/entities/Unit.ts, HUD в BattleScene
Не трогать: расталкивание, формацию приказа
Готово когда: в HUD видно, как мораль меняется при марше и восстанавливается
```

## 5. Definition of Done

- `npm run typecheck` проходит.
- Поведение проверено в игре (`npm run dev`).
- Обновлён `docs/GAME_DESIGN.md`: механика, формулы, статус.
- Если изменилось управление или состав отрядов — обновлён `README.md`.

## 6. Стиль ответа

- Кратко: что изменено, в каких файлах, что проверить руками.
- Без пересказа всего файла и без лишних комментариев в коде.
- Комментарии только там, где логика неочевидна (например, распределение
  расталкивания по массе).
